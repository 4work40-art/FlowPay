# Сводка проекта — Счёт&Контроль (FlowPay)

Дата: 12 августа 2026 · Статус: боевая версия развёрнута и доступна публично

## Что это

«Счёт&Контроль» — мультиарендный сервис учёта и контроля счетов, платежей,
контрагентов и товарной аналитики закупок для малого и среднего бизнеса РФ.
Прошёл несколько раундов независимых продуктовых/security-аудитов 2026 года;
все критические и большинство продуктовых находок реализованы (полный текст
находок — в git-истории, актуальный нерешённый остаток — в [ROADMAP.md](ROADMAP.md)).

## Доступ

| Что | Значение |
|---|---|
| Репозиторий | https://github.com/4work40-art/FlowPay |
| Сервер | TimeWeb Cloud VPS (Ubuntu 26.04, 1 CPU / 1 ГБ RAM) |

Адрес боевого сервера и учётные данные в репозитории не публикуются.

## Что сделано

### Продукт
- Мультиарендность: самостоятельная регистрация организации и владельца,
  изоляция данных по `org_id` из JWT на каждом запросе
- Полный цикл счетов (в т.ч. исходящих клиентам) и платежей: позиции,
  обязательный срок оплаты, статусы, пагинация, поиск и фильтры
- Умное распознавание документов (OCR + текстовые PDF + Excel/CSV-реестр)
  для счетов, счетов-фактур/УПД, платёжных поручений и банковских выписок;
  подключено и на создание, и на дозаполнение уже существующего счёта
- Контрагенты с обязательным валидируемым ИНН, предупреждением о дублях,
  автоподбором реквизитов по ИНН (DaData), ABC-ранжированием поставщиков
- Календарь оплат, товарная аналитика (динамика цены, сезонность закупок),
  прогноз денежного потока, возраст просроченной задолженности
- Публичная ссылка на счёт для контрагента без регистрации
- Биллинг ЮKassa с `organizations` как единым источником истины по тарифу
  и лимиту; отмена/даунгрейд подписки
- Приглашение коллег в организацию, публичный лендинг и тарифы без входа
- Кабинет платформы (`/admin`) с бизнес-метриками по всем организациям

### Безопасность
- Реальная авторизация: подписанные JWT, отзыв через Redis, восстановление
  пароля, rate limiting на вход/регистрацию
- **Устранена критическая уязвимость**: миграция назначения
  `is_platform_admin` переназначала флаг при каждом деплое — demo-аккаунт
  получал права platform-admin на каждое обновление прода. Теперь флаг
  назначается только вручную, разово, и никогда не трогается автоматически
  (см. README → «Безопасность и архитектура»)
- Мультиарендная изоляция данных, транзакционная защита остатков платежей,
  webhook ЮKassa не доверяет телу запроса

### Инфраструктура
- Docker Compose (Postgres, Redis, API, фронтенд), однострочный `deploy.sh`
- CI (GitHub Actions): синтаксис, unit-тесты, tsc
- Ежедневные автобэкапы БД, хранение 14 дней

### Дизайн
- Тёмная тема, глобальный поиск (⌘K), адаптивные таблицы — весь дизайн-долг
  из ТЗ v4.1 закрыт 11.08.2026
- **Устранена регрессия аудита v5 (12.08.2026)**: в тёмной теме статусы
  «Оплачен» и «Частично оплачен» рендерились одинаковым зелёным цветом —
  разведены на отдельные токены; баннер напоминаний об оплате не был
  подключён к теме — исправлено; необратимое действие «Списать» получило
  обособленный danger-стиль и перестало соседствовать по весу с безопасными
  действиями (подробности — в ROADMAP.md → «Аудит v5»)

### Локализация
Интерфейс и все сообщения API на русском языке.

## Известные ограничения (осознанно отложено)

| Ограничение | Причина |
|---|---|
| Нет HTTPS/домена | Решение владельца — единственный открытый блокер по итогам аудитов; работаем по IP/HTTP на этом этапе |
| Trust Score — описательная метрика, не предиктивная модель риска | Требует накопленной статистики; см. ROADMAP |
| Нет полноценной интеграции с ЭДО (СБИС/Диадок) | Намеренно вне текущего скоупа; см. ROADMAP |
| Нет повторяющихся/шаблонных счетов | Низкий приоритет, узкий кейс |
| 1 ГБ RAM на сервере | Достаточно для старта, может понадобиться апгрейд при росте нагрузки |
