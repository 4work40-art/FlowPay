# Счёт&Контроль (FlowPay)

Веб-сервис учёта и контроля счетов, платежей, контрагентов и товарной
аналитики закупок для малого и среднего бизнеса РФ. Мультиарендный SaaS
с самостоятельной регистрацией организаций — не банковское приложение и
не платёжный сервис: деньги через нас не проходят, продукт только
фиксирует факты выставления и оплаты счетов. ЮKassa используется
исключительно для оплаты собственных подписок сервиса.

## Возможности

- **Дашборд** с ключевыми показателями (задолженность, просрочка, платежи за
  месяц, Trust Score организации), онбординг-чеклист для новых организаций
- **Счета**: создание, детальная карточка, позиции (товары/услуги) с
  автоматическим форматированием количества, история платежей, обязательный
  срок оплаты (`due_date`), полный жизненный цикл статусов (создан → на
  контроле → ожидает оплаты → оплачен/просрочен/спор/списан/архив),
  пагинация в списках счетов и исходящих счетов
- **Исходящие счета**: выставление счетов клиентам с позициями, расчётом
  НДС, PDF/Excel-экспортом и отслеживанием статуса
- **Публичная ссылка на счёт** — контрагент может посмотреть статус и остаток
  долга без регистрации в системе (отключаемо владельцем счёта)
- **Платежи**: фиксация оплаты с проверкой остатка и блокировкой строки,
  поиск, фильтры, пагинация, экспорт в CSV
- **Календарь оплат** — визуальный план/факт платежей по срокам, с backfill
  для счетов, заведённых до того, как срок оплаты стал обязательным полем
- **Умная загрузка документов**: перетащите PDF/JPG/PNG счёта на оплату,
  счёта-фактуры/УПД или платёжного поручения — поля формы заполняются
  автоматически по полному набору реквизитов из законодательства РФ (номер,
  дата, сумма, ставка/сумма НДС, ИНН/КПП/ОГРН, банковские реквизиты
  плательщика и получателя, очередность платежа, УИН/КБК/ОКТМО). Работает и
  как дозаполнение уже существующего счёта на его странице. Платёжка сама
  находит нужный счёт по номеру в назначении. Текстовые PDF читаются
  напрямую, сканы и фото — через OCR (Tesseract, рус+англ) с предобработкой
  изображения. Файл нигде не сохраняется дольше одного запроса. Импорт
  реестра счетов из Excel/CSV (`/invoices/import`) и импорт банковской
  выписки (CSV и 1CClientBankExchange `*.txt`, включая windows-1251) —
  разбор, проверка каждой строки и пакетное создание. Всегда требует
  проверки перед сохранением
- **Контрагенты**: карточки с ИНН/КПП/ОГРН/банковскими реквизитами,
  обязательный и валидируемый ИНН с предупреждением о вероятных дублях,
  автоподбор реквизитов по ИНН (DaData), автоматический подсчёт долга,
  ABC-ранжирование поставщиков по объёму закупок
- **Товарная аналитика**: динамика цены за позицию, частота и объём закупки
  товара по месяцам (прокси сезонности без складского учёта)
- **Аналитика**: возраст просроченной задолженности (0–30 / 30–60 / 60–90 /
  90+ дней) с учётом Trust Score, прогноз денежного потока (недельные
  бакеты), журнал событий
- **Биллинг**: тарифы, оплата через ЮKassa, отмена/даунгрейд подписки;
  `organizations` — единственный источник истины по текущему тарифу и
  лимиту счетов (таблица `subscriptions` — вторичная, обновляется в той же
  транзакции)
- **Приглашение коллег** в организацию по email, публичный лендинг и
  страница тарифов без входа в систему. Роли внутри организации
  (`services/api-gateway/src/routes/users.js`):
  - `owner` — полный доступ, включая управление организацией (назначается
    автоматически при регистрации организации);
  - `accountant` — счета и платежи (чтение и запись);
  - `vendor_admin` — счета и платежи (только чтение) + управление
    поставщиками (`vendor:admin`) и чтение журнала аудита;
  - `readonly` — только чтение счетов и платежей, без права что-либо
    изменять; предназначена для наблюдателей (например, приглашённого
    инвестора или руководителя без операционных задач). Доступна как роль
    при приглашении (`INVITE_ROLES` в
    `services/api-gateway/src/routes/organizations.js`) наравне с
    `accountant`; из списочных API-роутов и переходов статусов счетов
    (`services/api-gateway/src/routes/invoices.js`) исключена наравне с
    `vendor_admin` от финансово необратимых действий (списание долга,
    открытие/закрытие спора).
- **Кабинет платформы** (`/admin`) — сводная статистика по всем
  организациям: рост, распределение по тарифам, активность, выручка.
  Отдельный, физически непересекающийся с клиентскими ролями доступ (см.
  «Безопасность» ниже)
- Фоновые задачи: авто-перевод счетов в «Просрочен» по сроку, дайджест
  просрочки по email, истечение платных подписок
- Реальная авторизация: подписанные JWT-токены, восстановление пароля,
  rate limiting на вход/регистрацию, отзыв токена через Redis при выходе

## Безопасность и архитектура

- **Мультиарендность**: `org_id` берётся из JWT, а не из тела запроса; все
  запросы к данным организации скоуплены по нему.
- **Доступ к кабинету платформы (`/admin`) — отдельная, непересекающаяся с
  клиентскими ролями учётная запись.** Флаг `is_platform_admin` в таблице
  `users` не назначается автоматически ни при каком деплое или повторном
  запуске миграций (`infra/postgres/migration_platform_admin.sql` только
  добавляет колонку) — назначение только вручную, разово, для конкретного
  администратора платформы. Это восстановленный принцип: ранее миграция
  переназначала флаг при каждом деплое, из-за чего demo-аккаунт получал
  права platform-admin на каждом обновлении прода — критическая уязвимость,
  устранена (см. `git log`, коммит «Fix critical access-control bug»).
- Пароли — bcrypt (pgcrypto); сброс пароля — через хэшированные одноразовые
  токены с анти-oracle ответом.
- Платежи — транзакция с `SELECT ... FOR UPDATE`, запрет переплаты,
  CHECK-констрейнты в БД.
- Webhook ЮKassa не доверяет телу запроса — статус перепроверяется через API.

## Технологии

- **Backend**: Node.js + Express + PostgreSQL (`services/api-gateway`) —
  модульная структура: `routes/` (auth, dashboard, invoices, payments,
  counterparties, outgoingInvoices, organizations, users, audit, admin,
  billing, documents, bankImport, analytics, public) и `lib/` (db, auth,
  http, audit, plans, inn, dadata, mailer, документ-распознавание,
  фоновые джобы и др.)
- **Frontend**: Next.js 14 (App Router) + TypeScript, чистый CSS без сборочных фреймворков (`apps/web-client`)
- **Инфраструктура**: Docker Compose (Postgres, Redis, API, фронтенд, Adminer, Redis Commander)
- **CI**: GitHub Actions — синтаксис, unit-тесты (`services/api-gateway/test`), tsc

## Локальный запуск

```bash
cp .env.example .env    # заполнить своими значениями (пароли, JWT_SECRET)
docker compose up -d --build
```

| Сервис | URL |
|--------|-----|
| Приложение | http://localhost:3000 |
| API Health | http://localhost:3001/health |
| Adminer (просмотр БД) | http://localhost:8080 (только с самого сервера) |
| Redis UI | http://localhost:8081 (только с самого сервера) |

**Adminer:** сервер `postgres`, пользователь `sk_user`, пароль — значение `POSTGRES_PASSWORD` из `.env`, база `schyot_kontrol`.

## Продакшн-деплой (VPS)

Однострочный скрипт `deploy.sh` ставит Docker, клонирует репозиторий, генерирует секреты, поднимает стек, применяет миграции и настраивает файрвол + автобэкапы:

```bash
curl -fsSL https://raw.githubusercontent.com/4work40-art/FlowPay/main/deploy.sh | bash -s <IP_СЕРВЕРА>
```

Повторный деплой на уже настроенном сервере:

```bash
cd /opt/FlowPay && git pull && ./deploy.sh <IP_СЕРВЕРА>
```

## Переменные окружения

См. `.env.example`. Обязательные: `POSTGRES_PASSWORD`, `REDIS_PASSWORD`, `JWT_SECRET` (от 32 символов — сервер откажется стартовать со слабым/пустым значением), `CORS_ORIGIN`, `NEXT_PUBLIC_API_URL`.

## Авторизация

Вход по email/паролю выдаёт подписанный JWT (24 часа). Все API-эндпоинты, кроме `/health` и `/auth/login`, требуют заголовок `Authorization: Bearer <token>`. Выход из системы отзывает токен через Redis.

## Бэкапы (боевой сервер)

Ежедневно в 03:00 по крону выполняется `backup.sh` — дамп БД в `backups/`, хранятся последние 14 дней.

Восстановить из бэкапа:
```bash
cd /opt/FlowPay
gunzip -c backups/schyot_kontrol_ФАЙЛ.sql.gz | docker compose exec -T postgres psql -U sk_user schyot_kontrol
```

## Диагностика

**Проверить API вручную:**
```bash
curl http://localhost:3001/health
curl -H "Authorization: Bearer <token>" http://localhost:3001/api/v1/dashboard
```

**Логи контейнеров:** `docker compose logs -f [сервис]`

**Полный сброс локальной БД:** `docker compose down -v && docker compose up -d --build`
